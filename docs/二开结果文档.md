# Niko-Agent 二开结果文档

> 面向面试展示与开发者理解的持续维护文档。原始需求以根目录 `Niko-Agent v1 二次开发计划.md` 为冻结基线；本文件记录实际实现、差异与验证证据。

## 项目总览

- 定位：本地、白盒代码 Agent，强调可审计运行证据、安全边界与可恢复会话。
- 入口：`niko` CLI；配置为 `.niko.toml` 与 `NIKO_*`；运行状态为 `.niko/`。
- 核心模块：`core/` 协调运行时、会话、权限与恢复；`tools/` 执行受策略约束的工具；`providers/` 管理模型 Provider；`features/` 提供 sandbox、记忆与技能；`evaluation/` 提供离线验收。

## 架构与模块地图

- `niko_agent/core/`：运行时、会话与事件、工具策略、检查点、工作区与敏感路径控制。
- `niko_agent/tools/`：文件、命令、计划、提问、子 Agent 等工具的 schema、注册和执行接口。
- `niko_agent/features/`：sandbox、记忆和 skills 的运行时能力。
- `niko_agent/evaluation/` 与 `scripts/`：离线验收、运行证据与验证门禁。
- `tests/`：pytest 与 pytest-asyncio 回归、验收和安全测试。

## 二开功能记录

### v1 本地交付审计（截至 2026-07-23）

- 目标与背景：完成 Niko 品牌迁移及安全恢复增强。
- 涉及文件：`niko_agent/`、`tests/`、`scripts/`、`docs/`、README 与发布元数据。
- 设计决策与取舍：敏感状态 fail closed；rollback 采用预览加一次性 token 的两阶段模型；Windows sandbox 无后端时 required 模式拒绝执行。
- 实现流程：完成品牌与配置迁移、敏感路径保护、fork/checkpoint/rollback、运行证据脱敏、Windows verifier 有界超时与评测。
- 接口与数据流：`niko` CLI → runtime/工具策略 → 会话与运行证据；`.niko/` 仅保存脱敏运行状态。
- 测试命令与结果：2026-07-29 使用当前虚拟环境执行 `scripts/verify.py --profile full`：337 passed、5 skipped、1 个 `.pytest_cache` 权限警告；Gate8 离线真实会话 9/9；确定性评测 12/12。Ruff 通过。
- 风险与限制：缺少历史 pico `4adae0b`；真实 Provider 烟测、远端推送与遗留进程处理需单独授权；Windows 当前无创建符号链接权限。超长临时路径约 269 字符时，session event 文件会触发经典 Windows 路径限制；短临时根下完整门禁通过，是否进行超长路径加固待确认。
- 关联提交：`53d9e33`、`d8718d6`、`bceee1a`、`d3a646c`、`123f160`。
- 后续优化：按用户授权处理外部验证；或确认后进行 Windows 超长路径持久化加固；否则开始 v2 功能需求。
